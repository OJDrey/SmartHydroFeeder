# Схема електрична принципова SmartHydroFeeder — чернетка

> Остаточна схема і перелік елементів — у `hardware/kicad/` (PDF: `smarthydrofeeder_E3.pdf`, `smarthydrofeeder_PE3.pdf`). Номінали там уточнено за купленими деталями: R3 220 Ом, VD2 1N5819, перистальтичний насос, розмикальний поплавок ZP2508, штирьові роз'єми X2–X4. Ця чернетка лишається як історія рішень.

Робоча чернетка для перенесення в KiCad. Піни взято з `src/config.h`. Позиційні позначення відповідають ЄСКД (ГОСТ 2.710).

Позначення документів:

- схема: `ХХХХ.ХХХХХХ.ХХХ Е3`;
- перелік елементів: `ХХХХ.ХХХХХХ.ХХХ ПЕ3`.

Шифр уточнити за зразком коледжу.

## Припущення, які варто перевірити

1. Живлення — один блок 5 В / 2 А через гніздо постійного струму.
2. Насос — мініатюрний на 5 В зі струмом до 0,5 А.
3. Зумер активний, на 5 В. Вмикати його треба через транзистор, а не прямо з GPIO4, бо струм зумера (≈ 30 мА) близький до межі піна. Прошивку міняти не треба: як і раніше, `HIGH` означає «увімкнено». У README зараз написано «Зумер — GPIO4»; після цієї зміни таблицю треба уточнити.
4. HC-SR04 на схемі показано як альтернативу тензодатчику (середовище `esp32dev`). Якщо в дипломі лишаєте лише ваги, A4, R1 і R2 можна прибрати.
5. Світлодіод на GPIO2 вбудований у плату DevKit, тому окремо на схему не виноситься.

Примітки до переліку:

- Якщо робити друковану плату, модулі A1–A4 ставляться на штирьові роз'єми. У переліку їх можна додати окремими рядками (X5…), а можна вказати в примітці до модуля.
- IRLZ44N при 3,3 В на затворі відкривається не повністю. Для насоса до 0,5 А цього вистачає, а на друкованій платі краще поставити AO3400. Остаточне рішення прийняти після вимірювань на макеті.

## Таблиця з'єднань

Запис `A1:GPIO33` означає вивід GPIO33 модуля A1.

| Коло | З'єднання |
|---|---|
| +5V_IN | X1:+ → VD2:анод |
| +5V | VD2:катод, A1:VIN (5V), C1:+, C2, M1:+ (через X3), VD1:катод, HA1:+, A4:VCC |
| +3V3 | A1:3V3, A2:VCC, A3:VCC, R5 |
| GND | X1:−, A1:GND, A2:GND, A3:GND, A4:GND, C1:−, C2, C3, R2, R4, VT1:витік, VT2:емітер, SB1, SL1 (через X4) |
| HX711_DT | A1:GPIO19 — A2:DT (DOUT) |
| HX711_SCK | A1:GPIO23 — A2:SCK |
| Тензоміст | B1 → X2 → A2: червоний E+, чорний E−, білий A−, зелений A+ (кольори перевірити за документацією датчика) |
| SDA | A1:GPIO26 — A3:SDA (підтягувальні резистори вже є на модулі) |
| SCL | A1:GPIO27 — A3:SCL |
| TRIG | A1:GPIO32 — A4:TRIG (рівня 3,3 В досить для HC-SR04) |
| ECHO | A4:ECHO → R1 → вузол → A1:GPIO35; вузол → R2 → GND (5 В × 2/3 ≈ 3,3 В) |
| PUMP | A1:GPIO33 → R3 → VT1:затвор; VT1:затвор → R4 → GND |
| PUMP− | VT1:стік — M1:− (через X3) — VD1:анод |
| FLOAT | A1:GPIO34 — R5 — +3V3; A1:GPIO34 — SL1 — GND; A1:GPIO34 — C3 — GND |
| BUZZER | A1:GPIO4 → R6 → VT2:база |
| BUZZER− | VT2:колектор — HA1:− |
| BUTTON | A1:GPIO25 — SB1 — GND (внутрішня підтяжка `INPUT_PULLUP`) |

## Перевірка пінів ESP32

- GPIO34 і GPIO35 працюють лише на вхід і не мають підтяжки. Тому для поплавка потрібен R5, а ECHO підключено через дільник.
- Ні GPIO33, ні GPIO4 не впливають на завантаження плати. R4 не дає насосу ввімкнутися на час завантаження.
- GPIO2 впливає на режим завантаження, але на ньому лише вбудований світлодіод, тож конфлікту немає.

## Як рахувати споживання

| Споживач | Струм, мА |
|---|---|
| ESP32 під час передачі Wi-Fi | до 250 (пікове) |
| Насос M1 | до 500 |
| HX711 + OLED + HC-SR04 | ≈ 40 |
| Зумер HA1 | ≈ 30 |
| **Разом** | **≈ 820** |

Отже, блока на 5 В / 2 А вистачає з дворазовим запасом.
