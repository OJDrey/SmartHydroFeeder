# SmartHydroFeeder

Розумна поїлка для дрібних домашніх тварин на базі ESP32. Пристрій вимірює рівень води в пляшці, показує його на OLED-дисплеї та надсилає сповіщення власнику через Telegram-бота.

## Склад

| Файл | Призначення |
|---|---|
| `src/` | Прошивка ESP32 (див. нижче) |
| `platformio.ini` | Налаштування збірки PlatformIO: плата і версії бібліотек |
| `wokwi.toml`, `diagram.json` | Симуляція в Wokwi для VS Code |
| `bot_v5.py` | Telegram-бот на Python: пересилає дані з MQTT у Telegram і приймає команди |
| `.env.example` | Шаблон налаштувань бота |

Обмін даними: ESP32 ⇄ MQTT-брокер ⇄ Python-бот ⇄ Telegram.

## Структура прошивки

| Модуль | Відповідає за |
|---|---|
| `main.cpp` | Створення об'єктів, `setup()` і `loop()` |
| `config.h` | Піни та всі константи |
| `settings.*` | Висота пляшки, інтервал, автозаміри; зберігання в NVS |
| `level_sensor.h` | Інтерфейс датчика рівня `LevelSensor` |
| `ultrasonic_sensor.*` | Реалізація для HC-SR04 |
| `scale_sensor.*` | Реалізація для тензодатчика з HX711: тарування, калібрування, мілілітри |
| `lib/refill/` | Скінченний автомат автодоливу (чиста логіка без Arduino, покрита тестами) |
| `buzzer.*` | Зумер: неблокуючі серії сигналів |
| `button.*` | Кнопка з антибрязкотом: короткий і довгий натиск |
| `screen.*` | Екрани OLED і тайм-аути їх показу |
| `net.*` | Wi-Fi (WiFiManager) і MQTT |
| `feeder.*` | Логіка поїлки: заміри, сповіщення, команди, меню |

Залежності йдуть в один бік: `feeder` використовує `LevelSensor`, `screen`, `net` і `settings`, але не знає, який саме датчик стоїть. Датчик вибирається прапорцем збірки `USE_SCALE_SENSOR`.

| Середовище | Призначення |
|---|---|
| `esp32dev` | Реальна плата з HC-SR04 (за замовчуванням) |
| `esp32dev_scale` | Реальна плата з тензодатчиком і HX711 |
| `wokwi` | Симулятор з HX711 |
| `wokwi_sonar` | Симулятор з HC-SR04 (у `wokwi.toml` змінити шлях до прошивки) |

### Налаштування ваг

1. Поставити на ваги порожню пляшку і надіслати боту `/tare`.
2. Поставити вантаж відомої ваги (наприклад, 200 г води) і надіслати `/calibrate 200`.
3. Вказати об'єм пляшки: `/capacity 500`.

Тарування і калібрування зберігаються в пам'яті плати.

### Автодолив

Насос вмикається, коли рівень нижче 20 % (якщо автодолив увімкнено командою `/refillon`) або за командою `/refill`, і вимикається на 90 %. Захисти:

- **поплавок** зупиняє насос незалежно від датчика рівня;
- **«насухо»**: якщо за 10 с рівень не зріс на 1 %, резервуар порожній;
- **тайм-аут** 5 хв на один долив;
- **пауза** 10 хв між автоматичними доливами.

Після помилки автодолив блокується до ручного `/refill`. Будь-яке натискання кнопки під час доливу зупиняє насос.

### Тести

```bash
pio test -e test
```

Тести автомата доливу запускаються на комп'ютері; компілятор PlatformIO завантажує сам.

## Підключення (ESP32)

| Пристрій | Пін |
|---|---|
| HC-SR04 TRIG | GPIO32 |
| HC-SR04 ECHO | GPIO35 (через дільник напруги 1 кОм / 2 кОм) |
| Кнопка | GPIO25 (на GND) |
| OLED SDA / SCL | GPIO26 / GPIO27 |
| HX711 DT / SCK | GPIO19 / GPIO23 |
| Насос (затвор MOSFET IRLZ44N) | GPIO33 (+ 10 кОм на GND) |
| Поплавок | GPIO34 (+ 10 кОм на 3V3), замикає на GND |
| Зумер | GPIO4 |
| Світлодіод | GPIO2 (вбудований) |

## Прошивка

Проєкт збирається в [PlatformIO](https://platformio.org/). Відкрийте цю папку у VS Code з розширенням PlatformIO IDE і натисніть **Upload** (→) на нижній панелі. Бібліотеки завантажаться самі за списком у `platformio.ini`.

Те саме з терміналу:

```bash
pio run -t upload      # зібрати і прошити
pio device monitor     # Serial Monitor, 115200
```

Якщо прошивка зависає на `Connecting...`, затисніть на платі кнопку BOOT.

Після першого запуску пристрій створює точку доступу `SmartHydroFeeder`. Підключіться до неї телефоном, відкрийте `192.168.4.1` і виберіть свою мережу Wi-Fi. Щоб скинути Wi-Fi, утримуйте кнопку під час увімкнення 3 с.

## MQTT-брокер

Без налаштувань пристрій і бот працюють через відкритий `broker.hivemq.com` (порт 1883, без пароля і шифрування). Будь-хто, хто знає `DEVICE_ID`, може читати дані й надсилати команди, тому для реальної роботи використовується хмарний брокер EMQX Cloud Serverless з TLS і паролем. Безкоштовної квоти (1 млн сесій-хвилин на місяць) вистачає з великим запасом: пристрій і бот разом використовують близько 90 тис. (Безкоштовний HiveMQ Cloud Serverless закрито для нових кластерів.)

1. Зареєструватися на [cloud.emqx.com](https://cloud.emqx.com) і створити деплоймент **Serverless** (Spend Limit = 0, щоб не було жодних платежів).
2. На сторінці деплойменту (**Overview**) скопіювати адресу (`xxxx.emqxsl.com`). Порт MQTT over TLS — 8883.
3. У розділі **Access Control → Authentication** додати двох користувачів: для пристрою (`device123`) і для бота (`bot`).
4. Прошивка: скопіювати `src/secrets.example.h` у `src/secrets.h`, вписати адресу, логін і пароль пристрою, перепрошити (і для Wokwi теж).
5. Бот: у `.env` вписати `MQTT_SERVER`, `MQTT_USERNAME`, `MQTT_PASSWORD` (облікові дані бота).

Пристрій перевіряє сертифікат брокера за кореневими сертифікатами в `src/ca_certs.h` (DigiCert Global Root G2 для EMQX, Let's Encrypt для інших брокерів), бот — за системним сховищем сертифікатів. `src/secrets.h` і `.env` у репозиторій не потрапляють.

Якщо пристрій не підключається, у Serial Monitor видно код помилки: `rc=-2` — немає з'єднання (адреса, порт або TLS, рядок `TLS error` поруч), `rc=4` — неправильний логін або пароль, `rc=5` — немає дозволу.

## Telegram-бот

```bash
py -m pip install -r requirements.txt
cp .env.example .env   # вписати токен від @BotFather і свій chat_id
py bot_v5.py
```

Команди: `/help`, `/measure`, `/stats` (тиждень) і `/stats day` (доба), `/setheight 20`, `/autoon`, `/autooff`, `/interval 10`, для ваг `/tare`, `/calibrate 200`, `/capacity 500`, для доливу `/refill`, `/stop`, `/refillon`, `/refilloff`.

- **Доступ:** бот виконує команди лише з чату `TELEGRAM_CHAT_ID` (і з `ALLOWED_CHAT_IDS` через кому, якщо задано).
- **Історія:** усі виміри (і автоматичні, і ручні) та події доливу записуються в SQLite (`smarthydrofeeder.db`, шлях змінюється через `DB_PATH`). У чат пишуться лише ручні заміри, сповіщення і події.
- **Аналітика:** `bot_storage.py` рахує споживання як суму зменшень об'єму відносно опорного значення. Долив і шум до 2 мл не рахуються, а повільне зменшення між замірами накопичується. `/stats` надсилає графік споживання за годинами (доба) або днями (тиждень) і середнє за добу.
- **Час:** пристрій синхронізує годинник через NTP і надсилає Unix-час; поки час не синхронізовано, бот бере час отримання повідомлення.
- **Сповіщення про низький рівень** надсилається один раз при падінні нижче 20 % і знову лише після підйому вище 25 %.

Тести аналітики: `py -m unittest test_bot_storage`

Файл `.env` містить секрети, а база — історію вимірювань; обидва в репозиторій не потрапляють.
